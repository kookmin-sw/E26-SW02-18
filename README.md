  # -Team Mission 2 (26.10.02)

  관찰된 불편함 정의
  
    1) 같은 강의실의 이전 수업이 빨리 끝나거나 늦게 끝나는 경우를 정확하게 알고 싶다.
    
    2) 특정 시간대에 학생식당에 사람들이 몰려 대기 시간이 길어지는 경우가 발생한다.
    
    3) 화장실이 고장나 있거나 혼잡한 경우 불편함을 느끼거나 다른곳을 계속 찾아다녀야 하는 문제가 발생
  
  AI Questioning을 통한 문제 구체화 
  
    1) 강의실을 이어 써야 하는 학생(사용자)은 유동적인 이전 강의 종료 시간 때문에 언제 이동해야 할지 모르는 불확실한 상황에서 무의미한 대기와 눈치 보기 등의 마찰 비용을 겪고 있으므로, 실시간 공간 상태 정보를 통해 이동 타이밍을 최적화하고 대기 시간을 없애줄 가시성 확보 솔루션(기대 효과)이 필요하다.
    
    2) 대학교 학생식당은 점심시간과 같이 특정 시간대에 학생들이 집중적으로 몰리면서 대기 줄이 길어지고, 식사까지 오랜 시간이 소요되는 문제가 발생한다. 이로 인해 학생들은 식사 시간을 효율적으로 활용하기 어렵고 다음 수업에 늦을 수 있다. 또한 학생들이 현재 학생식당의 혼잡도나 앞으로 붐빌 시간대를 미리 파악하기 어렵다는 점도 문제이다.
    
    3)  화장실이 고장나 있거나 혼잡한 경우 불편함을 느끼거나 다른 화장실의 상태를 모른채 주먹구구식으로 다른곳을 계속 찾아다녀야 하는 문제가 발생한다. 이로 인해 학생들은 수업시간에 늦는 등의 예기치 못한 피해가 발생하기도 하고 곤란한 상황을 마주할 수 있다.
  
  # -Team Mission 3 (26.10.02)
  
  아이디어 A
  
    : IoT 센서 기반 자동화 (IoT & Sensor-Based) 
    사람의 개입 없이 공간 자체의 변화를 감지하여 상태를 판별
    
    소음 및 조명 변화 감지: 강의 중일 때의 일관된 마이크 소리 패턴이 끊기고, 의자를 끄는 소리나 다수의 웅성거림(백색소음)이 급증하는 시점을 '수업 종료'로 인식하는 음향 센서를 활용
    
    출입구 비전/적외선 센서: 문 근처에 센서를 부착하여 한 번에 다수의 인원이 쏟아져 나오는 움직임이 감지되면 자동으로 공간이 비워지고 있음을 다음 수업 학생들에게 알림 (에브라타임 혹은 ON 국민)
    
    
    필요성: 수동 조작 없이 실시간으로 강의실 가용 상태를 파악해 학생들의 불필요한 대기와 혼잡을 즉각적으로 해결할 수 있음
    
    새로움: 정해진 스케줄이 아닌 실제 군중의 움직임 데이터를 감지해 자동 알림으로 연결하는 접근임
    
    실현 가능성: 시중의 저렴한 센서(ex. RPI)를 기존 교내 앱(ON국민, 에브리타임 등)과 연동하는 방식이라 도입 가능해 보임
    
    위험 요소: 쉬는 시간의 단순 인원 이동을 수업 종료로 오인할 가능성이 존재
  
  아이디어 B (문제 2)
  
    - 실시간 혼잡도 표시 시스템
        학생식당 입구 또는 학교 앱에서 혼잡도를 실시간으로 표시
        장점 : 학생들이 덜 붐비는 시간대를 선택할 수 있음
        단점 : 학생들이 정보를 보고도 특정 시간대에 몰릴 가능성
    
    - AI 혼잡도 예측 알림
        과거 이용량과 시간표를 분석해 “12:00 ~ 12:30 혼잡 예상” 등의 알림 제공
        장점 : 학생들이 미리 온 알림을 통해 스케줄 조정 가능
        단점 : 데이터 축적의 필요성과 예측 실패의 가능성
    
    
      사용자 필요 : 학생들은 특정 시간대에 학생식당이 얼마나 붐비는지 미리 알기 어렵고, 갑자기 긴 대기 줄을 마주하는 불편이 있음. 따라서 실시간 혼잡도와 AI가 예측한 한산한 시간대를 제공하는 서비스가 실제 학생들의 문제를 해결할 필요가 있는지 확인할 필요가 있음.
    
      실현 가능성 : 과거 학생식당 이용량과 학생들의 시간표를 분석하여 혼잡도를 예측하려면 학생식당 이용 데이터와 시간표 데이터가 필요함. 또한 실시간 혼잡도를 정확하게 측정할 수 있는 시스템도 구축해야 하므로, 실제 학교 환경에서 데이터를 확보하고 기술적으로 구현할 수 있는지 검토해야 함.
    
      개인정보 : 학생 시간표를 활용할 경우 학생의 수업 일정과 같은 개인정보가 수집·분석될 가능성이 있음. 따라서 개인별 시간표를 그대로 수집하기보다는 익명화하거나, 학생이 직접 자신의 이용 가능 시간을 설정하는 등의 방법으로 개인정보 침해를 최소화할 필요가 있음.
    
    
    놓치고 있는 숨은 가정
    → “정보를 제공한다면 수요가 분산된다.”
    
    검토 내용
    → 단순히 가장 한산한 시간대를 알려주는 시스템보다는 학생들에게 서로 다른 시간대를 추천하거나 시간대별 수용 가능 인원을 고려해 분산시키는 방식이 더 중요해질 수 있음.
  
  아이디어 C (문제 3)
  
  - 실시간 혼잡도 표시 시스템
      화장실 입구 또는 학교 앱에서 혼잡도나 화장실 고장 또는 사용중 여부를 실시간으로 표시
  
     장점
      1. 사용자 편의성 및 시간 절약: 학생들이 화장실에 가기 전 미리 사용 여부나 혼잡도를 확인하여 불필요하게 줄을 서거나 다른 층으로 이동하는 시간을 크게 줄일 수 있다.
      2. 시설 관리 및 정비 효율화: 화장실 고장(변기 막힘, 세면대 불량 등) 상태를 실시간으로 표시하고 앱으로 즉시 접수할 수 있어, 시설 관리팀의 유지보수 대응 속도가 빨라진다.
      3. 캠퍼스 내 혼잡도 분산: 특정 시간대(쉬는 시간, 점심 시간 등)에 특정 화장실로 사람이 몰리는 현상을 방지하고, 상대적으로 여유 있는 주변 화장실로 이용자를 유도할 수 있다.
  
     단점
      1. 초기 구축 및 유지보수 비용: 화장실 칸마다 재실 감지 센서(적외선, 마그네틱 등)를 설치하고, 이를 입구 디스플레이 및 학교 앱 서버와 연동하는 초기 설치 비용과 지속적인 통신·기기 관리 비용이 발생한다.
      2. 개인정보 및 인권 침해 우려: 화장실이라는 공간의 특성상 내부 센서 설치에 대한 이용자들의 심리적 거부감이나 불법 촬영(몰카) 관련 오해가 생길 수 있다. (반드시 카메라가 아닌 단순 물리 센서를 사용한다는 점을 명확히 공지해야 한다.)
      3. 센서 오류로 인한 정보 불일치: 센서가 오작동하거나(예: 사람이 없는데 문이 잠겨 있어 '사용 중'으로 인식), 고장 표시가 실시간으로 반영되지 않으면 시스템에 대한 사용자 신뢰도가 떨어질 수 있다.
      
  
  
    사용자 필요 : 학생들은 쉬는 시간이 제한적인 상황에서 특정 건물이나 층의 화장실이 얼마나 붐비는지 미리 알기 어렵고, 직접 방문했다가 만석이거나 고장으로 인해 헛걸음하는 불편이 있음. 따라서 화장실 입구 디스플레이나 학교 앱을 통해 실시간 혼잡도, 화장실 고정 여부, 사용 중 여부를 제공하는 서비스가 실제 학생들의 불편을 해소하고 이동 시간을 단축할 필요가 있는지 확인할 필요가 있음.
    
    실현 가능성 : 실시간 화장실 사용 정보를 정확하게 측정하려면 화장실 칸마다 사생활을 침해하지 않는 비카메라형 재실 감지 센서(마그네틱 또는 적외선 센서)를 설치하고 이를 학교 앱 서버나 입구 디스플레이와 연동해야 함. 또한, 미화원이나 시설 관리자의 정비 상태 및 학생들이 접수한 고장 데이터가 실시간으로 반영되는 시스템도 구축해야 하므로, 실제 학교 환경에서 인프라를 구축하고 기술적으로 구현할 수 있는지 검토해야 함.
    
    필요성: 화장실을 직접 방문하는 헛걸음 없이 실시간으로 칸별 사용 가능 여부와 고장 상태를 파악해 학생들이 제한된 쉬는 시간 내에 혼잡을 피하고 시간을 효율적으로 쓸 수 있음
    
    새로움: 정기적인 청소 시간이나 사후 고장 신고에 의존하는 것이 아닌, IoT 센서 데이터를 감지해 앱과 입구 디스플레이로 즉각 실시간 상태를 자동 업데이트하는 접근임
    
    위험 요소: 사람이 없는데 문이 잠겨 있거나 센서 오작동이 발생할 경우 '사용 중' 또는 '고장'으로 오인하여 멀쩡한 빈 칸을 방치하게 될 가능성이 존재

## Markdown을 사용하여 내용꾸미기를 익히세요.

Markdown은 작문을 스타일링하기위한 가볍고 사용하기 쉬운 구문입니다. 여기에는 다음을위한 규칙이 포함됩니다.

```markdown
Syntax highlighted code block

# Header 1
## Header 2
### Header 3

- Bulleted
- List

1. Numbered
2. List

**Bold** and _Italic_ and `Code` text

[Link](url) and ![Image](src)
```

자세한 내용은 [GitHub Flavored Markdown](https://guides.github.com/features/mastering-markdown/).
